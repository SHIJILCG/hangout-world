# Hangout World — Phase 5a: Meadow World — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the primitive park with the generated fantasy meadow (`client/public/models/fantasy-meadow.glb`): rolling wildflower meadow, wadeable river with a stone bridge, climbable ruins, distant mountain/castle backdrop — with full collision so movement, jumping, and multiplayer sync keep working.

**Architecture:** The meadow is produced by the procedural generator in `client/scripts/meadow/` (`scene.mjs` builds ~217 meshes, each tagged with `extras` metadata: `role`, `walkable`, `top`, `visualOnly`). This plan extends that generator to ALSO emit a collision manifest (`client/src/world/meadow-collision.json`) derived from the same data: an 81×81 heightfield grid sampled from `groundHeight(x,z)` (the exact function the terrain mesh uses) plus AABB boxes for solids. `CollisionWorld` gains heightfield-ground support (pure math, TDD). `map.ts` becomes async: it loads the GLB for visuals and builds `CollisionWorld` from the imported JSON. The world grows from 60×60 to 80×80 — a client+server contract change — and the server's y clamp gains a −1 floor for the riverbed.

**Tech Stack:** unchanged, plus three's `GLTFLoader` (already shipped in the installed `three` package under `three/addons`).

**Spec:** `docs/superpowers/specs/2026-09-19-hangout-world-design.md` (build phase 5's "map polish"; movement/physics behavior sections unchanged). Reference: `docs/fantasy-meadow.md` and `client/scripts/meadow/scene.mjs` (SPEC constants).

## Global Constraints

- All code is TypeScript with `"strict": true` (generator scripts stay plain `.mjs`).
- **World size contract change:** `WORLD_HALF` becomes **40** in BOTH `client/src/world/map.ts` and `server/src/constants.ts` (the "must match" pair). Border collision walls sit at ±40.
- **Vertical range:** server `validateMove` clamps y to **[MIN_Y = −1, MAX_Y = 10]** (new MIN_Y constant; riverbed reaches −0.8). Client physics needs no change — ground support comes from the heightfield.
- `SPAWN` stays `{x: 0, y: 0, z: 8}` (the meadow's center circle, radius 10, is flat at height 0 by construction — `groundHeight` is 0 for r < 11.5).
- **No-drift rule:** collision derives from the generator's own data (`groundHeight`, mesh extras, `bridgePoint`), never hand-typed coordinates. The manifest is regenerated by `npm run generate:meadow` (which must write BOTH the GLB and the JSON).
- Collision manifest shape (exact — Tasks 1/2/4 all depend on it):
  ```ts
  {
    "half": 40,
    "grid": { "min": -40, "step": 1, "size": 81, "heights": number[] /* 6561, row-major z-then-x: heights[(zIndex*size)+xIndex] at (min+xIndex, min+zIndex) */ },
    "boxes": Box[]   // {minX,minY,minZ,maxX,maxY,maxZ}, includes 4 border walls
  }
  ```
- Which meshes produce collision boxes (by `extras.role`):
  - SKIP (no collision): `backdrop`/`visualOnly`, `flowers`, `river`, `river-detail`, `tree-canopy`, `terrain` (terrain is the heightfield).
  - WHOLE-MESH AABB blockers: `fence`, `rock`, `ruin`, `ruin-rubble`, `tree-trunk`, `bridge-parapet`, `bridge-structure`. EXCEPTION: the 9 `Ruin arch voussoir` meshes and `Ruin stonework above arch` are skipped — they form the arch OPENING above y≈1.25 and an AABB would wall off the walk-through passage; the two pier stacks already block the sides.
  - WALKABLE, axis-aligned (whole AABB, exact `top` from extras): `ruin-step` (12 piles, tops 0.3→3.6), `ruin-crown` (top 3.6).
  - WALKABLE, 45°-rotated (`bridge-deck`, `bridge-step`): sliced into ≤0.5 m cells along the bridge's local u/v axes via `bridgePoint(v, u)` from scene.mjs, each cell emitted as an AABB with the element's exact `top` (deck top 1.0 spans v∈[−3.2,3.2], u∈[−1.6,1.6]; step i on each side has top 0.25·i, run 0.8, centered at v=±(6−0.8·(i−1))… read the extras, don't re-derive). Cell slop at 45° is ≤ ~0.35 m — accepted (players can stand marginally past the visual edge).
- Wading is ALLOWED: no bank walls; the river crosses via bridge OR on foot through knee-deep water (~−0.8 m). This is a deliberate design ruling.
- Rendering changes: scene fog moves out to `Fog(0x87ceeb, 120, 320)` and camera far plane to 400 so the 150–200 m backdrop is visible; loaded GLB meshes get `castShadow = receiveShadow = true` EXCEPT `visualOnly` backdrop meshes (castShadow false — the shadow camera only covers the playable area anyway).
- The overhead ruin arch means nothing to physics (the engine has no ceilings) — do not attempt to block it vertically.
- Commits: plain messages, NO Co-Authored-By trailers (owner's explicit preference).
- Astra's currently-untracked files (`client/scripts/meadow/*`, `client/public/models/fantasy-meadow.glb`, `client/meadow-preview.html`, `docs/fantasy-meadow.md`, the `client/package.json` script additions) get committed in Task 2 together with the manifest work.

### Task 1: Heightfield ground in CollisionWorld

**Files:**
- Modify: `client/src/world/collision.ts`
- Modify: `client/tests/collision.test.ts` (add cases; existing ones must keep passing unchanged)

**Interfaces:**
- Consumes: nothing new.
- Produces (Tasks 4's map and the existing controller rely on this exactly):
  ```ts
  export interface HeightGrid {
    min: number;       // world coord of heights[0] in both x and z
    step: number;      // grid spacing (1)
    size: number;      // samples per side (81)
    heights: number[]; // row-major, z-then-x: heights[zi * size + xi]
  }
  export class CollisionWorld {
    constructor(boxes: Box[], ground?: number | HeightGrid);  // number = flat (default 0) — EXISTING BEHAVIOR UNCHANGED
    groundAt(x: number, z: number): number;                   // NEW: bilinear interpolation, edge-clamped
    // supportHeightAt / resolveHorizontal keep their signatures; supportHeightAt's
    // base support becomes groundAt(x, z) instead of the flat constant.
  }
  ```
  Bilinear note: the rendered terrain triangulates each grid cell, so bilinear vs triangle interpolation differ by at most a few cm on these gentle slopes — accepted (ruled).

**Files:**

**Interfaces:**
- Consumes: `buildMeadow()`, `SPEC`, `groundHeight`, `bridgePoint` from `client/scripts/meadow/scene.mjs` (read that file first — the mesh `extras` metadata drives everything).
- Produces: `client/src/world/meadow-collision.json` in EXACTLY the manifest shape from Global Constraints (half 40; 81×81 row-major z-then-x grid of `groundHeight(x, z)` samples rounded to 3 decimals; boxes per the role table, plus 4 border walls at ±40, height 3, thickness 1, overlapping corners).

**Implementation guidance (derive, don't hand-type):**
- Grid: `for zi in 0..80: for xi in 0..80: heights.push(round3(groundHeight(-40 + xi, -40 + zi)))`.
- Whole-mesh AABB blockers: run `buildMeadow()`, and for each mesh whose role is in the blocker set, compute min/max of its (already world-transformed) `position` attribute. Skip the arch voussoirs/spandrel by name/role as ruled.
- Axis-aligned walkables (`ruin-step`, `ruin-crown`): whole-mesh AABB, but FORCE `maxY` to the `extras.top` value and `minY` to 0 (the visual pile includes tiny gaps; collision must be the clean stack).
- Rotated walkables: ignore mesh vertices; generate cells from `bridgePoint(v, u)`: deck cells over v ∈ [−3.2, 3.2], u ∈ [−1.6, 1.6] at 0.5 spacing, each cell's AABB = the 4 corner points' bounds, minY 0.6, maxY 1.0; per step (read `extras.step`, `extras.top`, side from the mesh name), cells over that step's v span (center ±0.4) and u ∈ [−1.6, 1.6], minY 0, maxY = top.
- Checks to add in `meadow.check.mjs` (node --test, run by `npm run test:meadow`):
  1. grid has 6561 entries; grid[center] === 0; every |height| ≤ 1.
  2. every box lies within ±41; border walls exist on all four sides.
  3. bridge walkability: walking the v axis from −7 to +7 at u=0, the support sequence (max of cell tops covering each sample point, else groundAt) never rises more than 0.3 per 0.4 m — i.e. the route is climbable.
  4. ruin route: the 12 ruin-step boxes have monotonically increasing tops 0.3→3.6 with rise exactly 0.3, and the crown box (top 3.6) horizontally touches or overlaps the last step's footprint.
  5. spawn area: no box overlaps the circle centre (0,0,8) radius 1; groundAt(0,8) === 0.
- `generate.mjs` writes BOTH artifacts; JSON is written compact (no pretty-print) to keep the bundle small.
